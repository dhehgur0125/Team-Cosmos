# VOID LAST — 눈 있는 대형 몬스터 프로토타입

테스트 씬: `Assets/Monster/Scenes/Monster_test.unity`.
몬스터: `Assets/Monster/Prefabs/VOID_LAST_EyedLargeMonster.prefab`.
기존 플레이어의 실제 경로: `Assets/Player/Prefabs/Player/VOID_LAST_FPS.prefab`.

작업 시작 시 Monster 폴더/씬은 없었습니다. 기존 AI Navigation 2.0.15를 사용했으며 패키지나 ProjectSettings는 변경하지 않습니다. 원본 FPS 프리팹·모델·손 애니메이션도 유지합니다.

## 직접 플레이

씬을 열고 Play를 누릅니다. 플레이어는 남쪽 외부 공간에서 시작하고, 몬스터 한 마리가 북쪽 복도를 순찰합니다. 기존 WASD/Shift/Ctrl/Space/마우스, 1번 권총/좌클릭/우클릭/R, 2번 근접 조작을 사용합니다. 플레이어 HP와 탄약은 기존 FPS HUD로 확인합니다. 몬스터 상태는 색상으로 구분하며 능력치는 Inspector에서 조절합니다. 다시 시작하려면 Play를 종료했다가 실행합니다.

복도 양쪽에 방이 있으며 왼쪽 출입구는 Z 0~3, 오른쪽은 Z 3.5~6.5입니다. 방 벽과 외부 엄폐물 뒤로 숨고, 마지막 목격 지점에서 벗어나 수색을 관찰할 수 있습니다. 닫힌 벽을 뚫고 이동하는 직선 추적은 사용하지 않습니다. 테스트에는 문 개폐 기능이 없습니다.

## 상태와 규칙

| 상태 | 동작 / 색상 |
| --- | --- |
| Patrol | 지정된 순찰 지점 중 직전과 다른 접근 가능한 지점 선택, 도착 후 1.2초 대기 / 청록 |
| Chase | 시야에 보이는 기존 대상 우선 추격 / 빨강 |
| Attack | 준비 중 정지·방향 고정·짧은 전방 돌진/타격·정지 회복 / 주황 |
| Investigate | 마지막 목격 위치 또는 대상 없는 직접 피격 시 공격 당시 위치로 이동 / 노랑 |
| Search | 마지막 위치 도착 후 주변의 접근 가능한 지정 수색 지점을 10초간 확인 / 노랑 |
| Return | 수색 실패 후 원래 순찰 지점으로 복귀 / 청록 |
| Dead | 이동·감지·공격 중지, Collider/Agent 해제, Capsule 쓰러짐 / 어두운색 |

거리 15m, 전방 수평 시야각 120도, 실제 Raycast 가림을 모두 검사합니다. 몸통 또는 상단이 보이면 감지하며 웅크리기 자체는 은신 판정이 아닙니다. 발소리·총소리·스캐너 이벤트는 구독하지 않습니다. 총알이 빗나가거나 벽에 맞으면 몬스터는 그 소리를 감지하지 않습니다.

기존 대상이 보이면 새 플레이어나 다른 사격자가 있어도 대상을 유지합니다. 기존 대상이 보이지 않을 때만 보이는 다른 대상으로 바꿀 수 있습니다. 사망·비활성 대상은 제외합니다. 가까운 다른 플레이어가 보이면 임시 공격할 수 있으나 추격 대상은 그대로 유지합니다. 네트워크 없이 같은 씬의 활성 `FpsHealth`와 CharacterController를 가진 플레이어들을 찾습니다.

직접 피격 시 대상이 없다면 공격자를 확인합니다. 시선이 가리지 않으면 공격받은 방향으로 돌아서 추격하고, 보이지 않으면 공격 당시 위치만 조사합니다. 이미 보이는 추격 대상이 있으면 피격으로 방향을 바꾸지 않습니다. 숨은 플레이어가 이후 움직여도 마지막 목격/피격 위치는 갱신하지 않습니다.

## 능력치와 공격

| 항목 | 기본값 / Inspector |
| --- | --- |
| 몬스터 HP | 300 — MonsterHealth |
| 권총 실제 피해 | 30 — FpsPistol.Damage, 정확히 10발 명중 시 처치 |
| 순찰 / 추격 속도 | 2 / 4.5m/s — EyedMonsterAI |
| 시야 거리 / 각도 | 15m / 120도 — MonsterVision |
| 수색 시간 / 반경 | 10초 / 9m — EyedMonsterAI |
| 근접 피해 / 시작 거리 | 30 / 2.5m — MonsterMelee |
| 준비 / 방향 고정 | 준비 0.3초, 돌진 0.12초 전 고정 |
| 돌진 | 0.2초 동안 1.5m (장애물·NavMesh 경계에서 단축) |
| 회복 | 0.8초 정지 후 추격 재개 — 총 공격 주기 약 1.3초 |
| 타격 활성화 | 돌진 시작 0.08초 뒤부터 돌진 종료까지 |
| 실제 타격 박스 | 폭 1m, 높이 1.9m, 전방 길이 2m |

기존에는 제자리에서 0.8초 기다린 후 2m 전방 범위를 한 번만 검사했습니다. 플레이어는 그동안 2.2m/s로 1.76m 후퇴할 수 있어 공격을 쉽게 벗어났습니다. 이제 준비 초기에는 대상을 향해 돌고, 돌진 0.12초 전부터 회전을 고정합니다. 이후 고정 방향으로 실제 몸체가 전진하며 Capsule 자식이 뒤로 젖혀졌다가 앞으로 기웁니다. 실제 모델·Animator는 없습니다.

전방 OverlapBox는 돌진 시작 0.08초 뒤부터 여러 번 검사합니다. 단순 후진 걷기를 잡을 수 있고, 방향이 고정될 때 측면으로 빠르게 빠져나가거나 벽으로 가리면 빗나갑니다. 회복 중에는 새 피해 판정이 없으며 Collider/프레임 수와 관계없이 같은 플레이어에게 한 번만 피해를 줍니다. 준비·돌진 중 사망하면 이동과 남은 판정을 즉시 취소합니다.

공격 중에는 Agent의 자동 위치·회전을 일시 중지하고, NavMesh 경계 검사와 실제 몸체 CapsuleCast/Overlap으로 허용된 직선 거리만 Agent.Move로 이동합니다. 짧은 이동 구간마다 충돌을 검사하므로 얇은 비베이크 장애물도 통과하지 않습니다. 장애물에서 멈추면 해당 돌진은 다시 밀고 나가지 않습니다. 회복 종료 시 현재 위치를 NavMeshAgent와 동기화하고 기존 AI에 제어를 반환합니다. 플레이어를 밀거나 벽을 따라 꺾이는 돌진은 사용하지 않습니다.

거리·시간·회전 속도·판정 크기·충돌 여유는 몬스터 프리팹의 `MonsterMelee` Inspector에서 조절합니다. `Attack Distance`는 시작 거리이고 `Hit Reach`는 실제 전방 판정 길이로 별개입니다. `Hit Start Delay`는 돌진 안의 타격 시작 지연입니다. 측면 회피를 더 쉽게 하려면 `Direction Lock Lead`나 이 지연을 늘리거나 `Hit Width`를 줄일 수 있습니다. 이번 변경은 Monster 내부에만 적용하며 이전 플레이어 연동 코드는 수정하지 않습니다.

플레이어 근접은 Monster_test의 플레이어 인스턴스에만 붙인 `MonsterMeleeTestBridge`로 연결합니다. 기존 근접 이벤트 후 0.25초에 전방 SphereCast를 검사하고, 벽을 먼저 맞히면 몬스터에게 피해가 가지 않습니다. 기본 20은 **테스트용 수치**이며 대형 몬스터 근접 처치 횟수를 확정한 것이 아닙니다. `Prototype Melee Damage`에서 조절합니다.

## NavMesh

기존 패키지의 NavMeshSurface에 별도 `Monster_test_NavMesh.asset`을 연결했습니다. 실제 몸체는 반경 0.7m·높이 2.8m이며, 모서리에서의 겹침을 방지하도록 베이크 반경을 0.85m로 설정했습니다. 테스트 바닥/벽 Collider만 수집하고 벽과 엄폐물 윗면은 걷기 불가 영역입니다. Agent 경로는 Complete인 경우만 사용합니다. 순찰/수색 후보가 없거나 접근 불가능하면 정지/재시도하며 벽을 무시한 이동으로 대체하지 않습니다.

이 데이터는 생성 시 배치된 정적 구조용입니다. 맵 구조를 바꾸면 Monster_test를 연 상태에서 `VOID LAST > Monster > 3 - Rebake Prototype Navigation`을 실행해 같은 큰 Agent 치수로 다시 베이크합니다. 기존 NavMesh 에셋의 GUID와 씬 배치는 보존합니다. NavMeshSurface의 기본 Bake 버튼은 프로젝트 기본 Agent 치수를 사용하므로 이 프로토타입 전용 메뉴를 사용하세요. 프로젝트 Agent 설정은 변경하지 않았습니다. 현재 프로토타입에는 동적 문·NavMeshLink·다층 계단이 없습니다.

## 파일과 기존 플레이어 연동

몬스터 런타임: `Scripts/MonsterHealth.cs`, `MonsterVision.cs`, `MonsterMelee.cs`, `EyedMonsterAI.cs`, `MonsterMeleeTestBridge.cs`.

설정/검증: `Scripts/Editor/MonsterPrototypeSetup.cs`, `MonsterValidation.cs`, MCP 연결 보조 `Invoke-MonsterMcp.ps1`. 메뉴 `VOID LAST > Monster > 1`은 씬이 없을 때만 생성하며 기존 씬을 덮어쓰지 않습니다. `2`는 실제 Play Mode 검증입니다.

에셋: 몬스터 프리팹 1개, 씬 및 NavMesh 데이터, `Materials/`의 바닥·벽·엄폐물·몬스터·눈 머티리얼, 이 문서와 `Validation/` 결과/렌더 캡처. 신규 Unity 에셋의 `.meta`도 포함합니다.

초기 프로토타입의 플레이어 연동 (이번 근접 개선에서는 변경 없음):

- `Assets/Player/Scripts/IFpsDamageTarget.cs` 추가: 몬스터 종류에 의존하지 않는 명중 피해 수신 인터페이스.
- `FpsPistol.cs`: 기존에는 피해 수치가 없었으므로 Inspector 피해 30과 수신 대상 호출 추가. 실제 Raycast 명중에만 적용합니다. 피해 대상에는 환경 탄흔을 붙이지 않습니다.
- `FpsPistolEffects.cs`: 피해 수신 캐릭터를 환경 불꽃에서 제외합니다. 몬스터 피격 이펙트는 아직 없습니다.

FPS 프리팹·이동·아이템·UI·손/Animator 코드는 수정하지 않습니다. 실제 플레이어 HP 피해는 기존 `FpsHealth.TakeDamage()`를 호출합니다.

## 검증 범위

`Validation/PlayModeResults.txt`의 최신 실행 시각과 최종 결과를 확인하세요. 실제 Unity의 NavMeshAgent·Physics·CharacterController·Raycast·HP·권총을 사용하며, 입력은 동작 API로 전달합니다. 물리 키보드/마우스 조작감이나 네트워크 검증은 아닙니다. 보이지 않는 사격자에 대한 반응 분기는 피해 API로 별도 검사하며, 벽을 관통하는 실제 총알을 허용하지 않습니다.

2026-11-01 (한국 시간) 근접 개선 후 실제 Play Mode 자동 검증 **86개 판정 통과**. 기존 순찰·문 통과·시야·대상 유지/전환·수색/복귀·권총 10발 사망·탄약/재장전/이동 검사를 유지하고 다음 돌진 검사를 추가했습니다.

- 실제 FpsMotor로 2.45m 거리에서 S 후진 걷기: HP 100 → 70, 한 번만 피해.
- 실측: 준비 0.309초, 돌진 종료 0.504초, 회복 종료 1.308초, 장애물 없는 전진 1.500m.
- 방향 고정 시 측면으로 돌아 W+Shift 달리기: 실제 CharacterController 이동으로 회피, 돌진 방향은 그대로 유지. 일반 A/D 걷기로 회피 가능하다고 검증한 것은 아닙니다.
- 여러 Collider/여러 판정 프레임에도 피해 30 한 번만 적용.
- 베이크되지 않은 두께 5cm 벽: 몸체 전진 차단 및 벽 너머 피해 없음.
- NavMesh 끝에서 돌진 거리 제한, 0.8초 회복 중 정지, 이후 기존 AI 추격 재개.
- 준비 및 실제 돌진 도중 사망: 즉시 이동·남은 공격 취소.

실행 중 기존 Vivox 편집기 서비스에서 HTTP 403이 발생해 Error Pause로 한 차례 멈췄습니다. 해당 서비스/설정은 수정하지 않고 재개했으며 검증은 끝까지 통과했습니다. 몬스터 코드의 컴파일 또는 실행 오류와는 별개입니다.

개발자가 추가로 확인할 사항: 실제 도주/옆 회피 체감, Capsule의 크기와 공격 판정 폭, 방 구조/수색 지점 배치, 원래 게임의 실내·외 맵과 여러 플레이어 배치. 실제 몬스터 모델·애니메이션, 소리 감지, 보스 패턴, 네트워크 동기화는 구현하지 않습니다.
